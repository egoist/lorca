# Coding agent roster

An agent's card travels with its chat to every Device, so each Device lists every coding agent on the account, whichever bot, chat, and Runner started it, from the cards in its own store (`agent_roster.rs`: `LocalStore::agent_rows`, the rows whose `Body::Tool` carries `agent`). Each lists with the chat's id and title, the row's id, and the bot's id and name beside its card, which names its Runner (`device`, `device_id`), folder, branch, state, pull request, and the repository its folder is a clone of (`repository`, from its `origin` remote: `github.com/egoist/lorca`, however the remote spells it). Open agents come first, then the rest, each latest first; one that ended or sat idle more than 30 days ago is left out. An agent is live while it is open and has not sat idle for three days, as the chat's Coding section judges it.

- The bot: `coding_agent list` with `scope: "account"` answers a line per agent ("agent-3f9a2c1d Claude Code “Login”: working, for Scout (bot-…) in “Shop” (chat-…) on Workbench, in ~/dev/shop on fix-login, its pull request"), "yours" for its own; `query` keeps the agents whose id, title, folder, branch, repository, pull request, bot, or chat contains it, so a pull request's link finds whose it is. `list_teammates` carries each bot's live agents.
- A start: before it starts, Lorca looks for agents already at work where it starts: live ones in the same folder on the same Runner, or a folder inside the other, or in a clone of the same repository on any Runner, and ones that failed there in the last day, which are often started again on their session. The start's answer names each, whose it is and on what, and tells the bot to tell the user, who decides whether to stop one: it starts either way, since two agents on one repository is sometimes what the user wants. A `send` that starts a stopped agent again says the same of the others.
- The apps: `coding.list {}` answers `{ agents: [{ chat_id, chat_title, message_id, bot_id, bot_name, agent }] }` from the Device's own store, so it needs no Runner online. A Device lists the agents in the history it holds: after its first sync, the newest 400 messages of each chat ([Relay](relay.md)).
