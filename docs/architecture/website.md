# Website

`web/` is the app's site: TanStack Start (React, file routes under `web/src/routes`), Tailwind and shadcn/ui components, built with Vite and served by a Cloudflare Worker (`web/wrangler.jsonc`, `@cloudflare/vite-plugin`, static assets alongside the SSR entry). One page: hero, screenshots of the app in `LORCA_MOCK=1` mode (`web/public/screens`), features, how it works, privacy, FAQ. The product docs are at `/docs`: MDX under `web/content/docs` (`meta.json` orders the sidebar), compiled by the `fumadocsMdx` Vite plugin and loaded in `src/lib/source.ts`, in English at `/docs` and Chinese at `/zh/docs` (`bots.zh.mdx` beside `bots.mdx`, `meta.zh.json` beside `meta.json`; a page with no translation falls back to English), rendered by Fumadocs UI (`src/components/docs/page.tsx`, shared by the routes `docs/$.tsx` and `zh_/docs/$.tsx`) with the site's own color tokens (`fumadocs-ui/css/shadcn.css`) and the system's appearance, which a script in the root shell (`src/routes/__root.tsx`) keeps as `.dark` on `<html>`. `/api/search` is the Orama index built from the same source, one per language, with the Mandarin tokenizer for Chinese; `/docs/<page>.md`, `/llms.txt`, and `/llms-full.txt` serve the pages as Markdown, with the Chinese ones under `/zh`. The download page (`src/components/site/download.tsx`, at `/download` and `/zh/download`) links the Mac app's disk image from the Sparkle appcast, which the server reads on each request, the Windows and Linux app's files from its newest published `desktop-v` release: the installer, the release's `install.sh` as a `curl … | sh` command, and the Debian packages, and the Android app's APK from its newest published `mobile-v` release. The build reads those releases from the GitHub API once, in one request (`src/lib/releases.ts`, `define` in `web/vite.config.ts`, with `GITHUB_TOKEN` or `GH_TOKEN` when set), so a new release reaches the page with the next deploy. A release build that can't read the desktop release stops; the dev server warns and leaves those buttons disabled. No Android release with its APK leaves that card coming soon. Its CLI commands fetch `web/public/install-cli.sh` and `install-cli.ps1`, which `web/public/_headers` serves as UTF-8 text (see [Installing the CLI](runtime.md#installing-the-cli)). `/models/v1.json` and `/marketplace/v1.json` are the model catalog and the marketplace index every Device checks for a newer one: the `servedFiles` plugin in `web/vite.config.ts` writes `crates/models/catalog.json` and `crates/cli/marketplace/index.json`, minified, to `web/public/models/v1.json` and `web/public/marketplace/v1.json` (ignored by git) when the dev server or a build starts, and Cloudflare serves them as static files with an ETag, so a check is a 304 until the file changes. The production Worker deploys from the `website` branch: Cloudflare builds and deploys it on every push there, so a deploy is a push of main to that branch (`git push origin main:website`), and the site serves the files main has (see [Providers](providers.md) and [Marketplace](marketplace.md#the-index)). `bun run web` serves it locally on port 3000; `bun run web:deploy` builds the checkout and runs `wrangler deploy` by hand.
