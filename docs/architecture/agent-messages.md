# The user and an agent

What passes between the user and a coding agent or a [subagent](subagents.md) directly, without the bot: what the user writes to it on its page, and what it asks the user on a card. Both go through `crates/cli/src/coding/` ([Coding agents](coding-agents.md)) and the chat's permission path ([Bot permissions](bot-permissions.md)).

## The user writes to it

The agent's page has a composer that writes to the agent itself, after Cursor's: `coding.send { chat_id, message_id, text }`, served on the Runner (sealed to it from any other Device), runs the bot's own `send` (`coding::send`, `Sender::User`), without `interrupt`, so the agent takes the message up when it would take the bot's: at its next step, whatever it is running. Stop then a message is how the user cuts in: a stopped agent with a session starts again on it. A message waits in the agent's queue (`Agent.queued`) from when it is sent until the agent reports it as a `prompt` step, which then carries `from: "user"` (the bot's carry none), and the queue empties when the agent stops or its process ends. `coding.send` waits up to 12 seconds for the message to reach the agent, within a sealed request's 20; an agent that takes longer to start again goes on, and its row says how. A refusal ("Claude Code is still starting.", "… ended before its session began", "… is no longer installed on this Runner.") is the answer, and nothing reaches the chat.

What the user wrote goes in the chat as their message to the agent: `Body::AgentMessage` with `Author::You`, which the apps show as "You messaged ⬢ Title · its first line" and which counts as nothing unread, pushes nothing, and starts no turn. The bot reads it in its history as "[The user wrote to Claude Code (agent-…), your coding agent on “Title”, directly; it has the message]: …", and the tool tells it not to pass that on again; its `read` marks such a prompt `> (from the user)`. Auto-review reads it as the user's words, `User, to the Claude Code on “Title”: …`, so what the agent then does is weighed against it as against the user's messages to the bot, and every command still passes the bot's Access and Auto-review and asks on a card as before. The message changes nothing else: what the agent said last stays unheard until a turn reads it, so one that failed and that the user started again from its page still wakes its bot, which hears it has been started since; its next report wakes the bot to relay it as any does; the agent's run time counts toward the turn that last gave it work; and an agent a routine or an event started is no longer `unattended`, since the user is at its page to answer what it asks.

## Its questions

An agent that asks the user something (Claude Code's `AskUserQuestion`, Codex's `item/tool/requestUserInput`) reports `driver::Event::Ask` with its questions, and Lorca puts them on a card at the end of the chat, where the user reads however far up the agent's row is (`coding::ask_question`), as Claude Code shows them in its terminal. The card is the bot's `Body::Permission` with `tool: "question"`, `plugin_id: "coding_agent"`, the agent's name, a `summary` (the first question, "… (+2 more)" for several), a `reason` ("Claude Code, the coding agent on “Title”, asks you."), and `question: { questions: [{ id, header, question, options: [{ label, description }], multi_select }], answers? }`: one to four questions, each with its choices or none. A question's `id` is what the agent knows it by: its text for Claude Code, its id for Codex. A Codex question marked secret (`isSecret`) stays off the card and unanswered, since the card and its answers show on every Device.

The card waits as an agent's permission card does (`Asker::Aside`, `PERMISSION_TIMEOUT`): the user's messages to the bot leave it up, the agent's row reads `asking`, it counts as unread, and a Runner pushes it to the phones as "Asks: …" ([Notifications](notifications.md)). One question waits at a time. `chats.permission { chat_id, message_id, decision: "allow", answers: { <id>: text } }` answers it from any Device, sealed to the Runner as `permission.answer` ([Requests between Devices](requests.md)): each answer is an option's label, several joined with ", " for a multi-select question, or the user's own words, and an allow without one is refused ("Answer the question first."). The Runner keeps the answers on the card (`coding::answer_question`), with saved secrets replaced by their placeholders, before the agent hears them, so every Device shows what was picked. `decision: "deny"` skips it.

What the agent hears:

- **Claude Code**: its `can_use_tool` request for `AskUserQuestion` is allowed with the answers in its input (`updatedInput: { …, answers: { <question>: <answer> } }`), the way Claude Code's SDK answers it; skipped, with no answers, which Claude Code reads as the user skipping it. Nobody answering in time, or nobody to answer, denies the call saying why and to decide itself and say so in its report.
- **Codex**: its request is answered `{ answers: { <id>: { answers: [<answer>] } } }`, or with no answers.

An agent a routine's run or an event started (`Record.unattended`) has nobody to answer: its question is not put up, and it hears so at once. Stopping the agent dismisses its card.

The apps draw the card with the reason, then each question's header, its text, and its choices with their descriptions, one or several to pick, and a field for the user's own words, with Submit (once every question has an answer) and Skip; answered, it shows "Answered: …" for each, or Skipped, No answer in time, or Dismissed. The Windows and Linux app draws it in the transcript (`questionCard` in `desktop/cards.go`); the phone's row opens a sheet for it (`src/ui/QuestionSheet.tsx`).
