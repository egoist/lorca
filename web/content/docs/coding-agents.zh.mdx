智能体可以把一项编程工作交给它 Runner 上的编程智能体：**Claude Code**、**Codex**、**OpenCode**、**pi** 或 Vercel 的 **fx**。智能体用你的原话转达你的要求，并告诉你已经交出去了。怎么做由编程智能体自己决定，它会 push 自己的工作、开 pull request，并向你汇报，附上它运行过的命令和输出；智能体随后把这份汇报转述给你。成果由你来审，智能体不会替你检查。

## 启动

对智能体说：

> 修好 ~/dev/app 里那个时好时坏的登录测试，然后开一个 pull request。

智能体会给这项工作起一个简短的标题，把你的要求连同仓库所在的位置一起转达，然后启动编程智能体，聊天里会出现带编程智能体图标的 **已发消息给 ⬢ 登录：修好不稳定的测试**。启动需要智能体的[访问权限](/zh/docs/access)里允许 **Shell 命令**。

智能体不会另加自己的计划、清单或指示。编程智能体就在智能体指出的仓库里工作，和你在终端里直接启动它一样：怎么做、在哪做、用哪个分支（包括要不要另开 worktree）、怎么检查，都由它自己决定。除非你另有说明，它会 push 并开 pull request。对做法有要求，比如不要动你的工作副本、不要开 pull request，就写在你的要求里，它会原话传给编程智能体。

## 用哪一个

每台运行智能体的电脑都有自己的一份列表，按你的偏好顺序列出这五个，每个都有开关。在 **设置 → 编程智能体** 里先在顶部选中那台电脑（手机上在 **设置** 里点进那台电脑）。列表会显示每个编程智能体是否已安装、版本是多少，拖动可以调整顺序。智能体默认用它所在电脑上排在最前、已开启且已安装的那一个，除非你指定了别的（“让 Codex 来做”）。在那台电脑上安装编程智能体并登录，和在终端里用它时一样。

## 它能做什么

编程智能体运行的每条命令，都和你的智能体自己的命令一样，要经过智能体的访问权限和[自动审查](/zh/docs/auto-review)。只读取的命令、以及在它工作的文件夹里的操作会直接运行；push 或部署这类操作，会对照你最初的要求来判断。自动审查需要问你时，编程智能体标记下方的卡片会显示“Claude Code 想要运行命令”，附上命令和 **允许一次**、**始终允许**、**拒绝**，任何一台设备上都能回答。

智能体可以把它为命令保存的[密钥](/zh/docs/secrets)交给编程智能体使用，比如发布软件包用的 `NPM_TOKEN`。密钥在编程智能体的环境变量里；它的记录和消息里只显示密钥的名字，不显示值。

## 跟进进展

点聊天里编程智能体的标记，或者聊天详情里 **编码** 下它的那一行，就能打开它的页面：智能体交代了什么、它想了什么说了什么、浏览了哪些文件、运行了哪些命令、改了哪些地方（增减了多少行），以及它的计划，都会实时显示。页面上有它的分支和 pull request，工作时还有 **停止**。页面是只读的：想改方向，就告诉智能体，由它把你的话原样转给编程智能体。

**编码** 列表显示每个编程智能体的标题和当前状态：**工作中**、**需要处理**（在等你回答）、**待审核**（已完成并开了 pull request）、**已完成**、**运行失败** 或 **已停止**。

## 做完之后

编程智能体完成后，它的汇报会以 **来自 ⬢ 登录：修好不稳定的测试 的消息** 出现在聊天里，并像回复一样通知你：做了什么、为检查运行了哪些命令及其输出、pull request 的链接。点开可以看完整的汇报和记录。随后智能体会回复一条消息转述这份汇报：编程智能体的结论、pull request，以及它运行过的命令和结果，汇报里缺了什么也会指出。这条回复只做转述：智能体不会去看代码、构建、测试或验收成果，也不会给编程智能体下新的指示；缺了什么，告诉智能体，它会转给编程智能体。编程智能体自己停下时，也会这样说明原因，由智能体告诉你发生了什么。

聊天里的 **停止** 会连同智能体的工作一起停掉聊天里的编程智能体。退出 Lorca 会停止正在工作的编程智能体；已经做完的，之后还能再收到消息，从上次停下的地方继续。编程智能体的运行时间，计入启动它的那一轮的[上限](/zh/docs/limits)。
