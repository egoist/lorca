智能体可以把一项编程工作交给它 Runner 上的 **Claude Code** 或 **Codex**，并负责监督：编程智能体独立干活，你的智能体读它的进展、给它补充指示，做完后把 diff 和 pull request 告诉你。

## 启动

对智能体说：

> 让 Claude Code 修好 ~/dev/app 里那个时好时坏的登录测试，然后开一个 pull request。

Runner 上要装有 Claude Code 或 Codex，并且在终端里能找到它。没有指定时，优先用 Claude Code，没有再用 Codex。启动需要智能体的[访问权限](/zh/docs/access)里允许 **Shell 命令**，并经过[自动审查](/zh/docs/auto-review)：需要问你时，卡片会显示“Developer 想要在 Workbench 上启动 Claude Code”，下面是 **允许一次**、**始终允许** 和 **拒绝**。

在 git 仓库里，编程智能体从不直接改你的工作副本。它会在 Lorca 的文件夹里得到一个自己的 worktree，基于仓库当前的提交新建一个分支，分支名取自这项工作。之后的工作可以在同一个分支上继续。不是仓库的文件夹，就直接在里面工作。

## 在哪里运行

- Runner 上正在运行 Herdr 时，编程智能体会在一个专属 Herdr 工作区的窗格里运行。
- 否则，如果正在运行 Luvus，就在一个 Luvus 工作区里运行。
- 都没有时，由 Lorca 在后台运行它。

在窗格里，你可以看着它工作，也可以自己往里输入。

## 它能做什么

编程智能体运行的每条命令，都和你的智能体自己的命令一样，要经过智能体的访问权限和自动审查。只读取的命令、以及在它自己 worktree 里的工作会直接运行；push 或部署这类操作，会对照你最初的要求来判断。自动审查需要问你时，编程智能体的卡片会显示“Claude Code 想要运行命令”，附上命令和同样的几个选项，任何一台设备上都能回答。编程智能体自己在窗格里提问时，卡片会显示“Claude Code 在询问”，附上它的选项，或者一个供你 **回答** 的输入框。

智能体可以把它为命令保存的[密钥](/zh/docs/secrets)交给编程智能体使用，比如发布软件包用的 `NPM_TOKEN`。持有密钥的编程智能体一律在后台运行，绝不放进可能把密钥显示出来的窗格里。

## 卡片

编程智能体的卡片会一直留在聊天里：它的名字、交给它的任务、当前状态（正在启动、正在工作、暂无进展、完成、已结束、失败或已停止）和所在分支；工作时还会显示最新的几行输出。点它正在做的内容，可以读完整记录；在 Runner 上还可以显示它的窗格。卡片上的 **停止** 会结束它。

## 做完之后

编程智能体完成后，Lorca 会把它的成果作为智能体的[输出](/zh/docs/chats#输出)发到聊天里：所有改动的 diff、它开的 pull request，以及它作为证明保存的测试日志和前后对比截图。然后智能体读完编程智能体说的话，向你汇报，或者再给它补充指示。编程智能体十分钟没有任何新进展，或者退出了，也会唤醒智能体。

聊天里的 **停止** 会连同智能体的工作一起停掉聊天里的编程智能体。退出 Lorca 会停止由它在后台运行的编程智能体，窗格里的则继续运行。编程智能体的运行时间，计入启动它的那一轮的[上限](/zh/docs/limits)。
