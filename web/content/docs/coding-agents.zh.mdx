智能体可以把一项编程工作交给它 Runner 上的编程智能体：**Claude Code**、**Codex**、**OpenCode**、**pi** 或 Vercel 的 **fx**。编程智能体在自己的分支里独立干活；你的智能体会告诉你已经交出去了，等编程智能体做完再检查它的成果，然后告诉你结果，有 pull request 时一并附上。

## 启动

对智能体说：

> 修好 ~/dev/app 里那个时好时坏的登录测试，然后开一个 pull request。

智能体会给这项工作起一个简短的标题、写好说明，然后启动编程智能体，聊天里会出现带编程智能体图标的 **已发消息给 ⬢ 登录：修好不稳定的测试**。启动需要智能体的[访问权限](/zh/docs/access)里允许 **Shell 命令**。

在 git 仓库里，编程智能体从不直接改你的工作副本。它会在 Lorca 的文件夹里得到一个自己的 worktree，基于仓库当前的提交新建一个分支，分支名取自这项工作。之后的工作可以在同一个分支上继续。不是仓库的文件夹，就直接在里面工作。

## 用哪一个

**设置 → 编程智能体** 按你的偏好顺序列出这五个，每个都有开关；在电脑上还会显示它是否已安装、版本是多少。智能体默认用它 Runner 上排在最前、已开启且已安装的那一个，除非你指定了别的（“让 Codex 来做”）。在智能体运行的那台电脑上安装编程智能体并登录，和在终端里用它时一样。

## 它能做什么

编程智能体运行的每条命令，都和你的智能体自己的命令一样，要经过智能体的访问权限和[自动审查](/zh/docs/auto-review)。只读取的命令、以及在它自己 worktree 里的工作会直接运行；push 或部署这类操作，会对照你最初的要求来判断。自动审查需要问你时，编程智能体标记下方的卡片会显示“Claude Code 想要运行命令”，附上命令和 **允许一次**、**始终允许**、**拒绝**，任何一台设备上都能回答。

智能体可以把它为命令保存的[密钥](/zh/docs/secrets)交给编程智能体使用，比如发布软件包用的 `NPM_TOKEN`。密钥在编程智能体的环境变量里；它的记录和消息里只显示密钥的名字，不显示值。

## 跟进进展

点聊天里编程智能体的标记，或者聊天详情里 **编码** 下它的那一行，就能打开它的页面：智能体交代了什么、它想了什么说了什么、浏览了哪些文件、运行了哪些命令、改了哪些地方（增减了多少行），以及它的计划，都会实时显示。页面上有它的分支和 pull request，工作时还有 **停止**。页面是只读的：想改方向，就告诉智能体，由它给编程智能体补充指示。

**编码** 列表显示每个编程智能体的标题和当前状态：**工作中**、**需要处理**（在等你回答）、**待审核**（已完成并开了 pull request）、**已完成**、**运行失败** 或 **已停止**。

## 做完之后

编程智能体完成后，它说的话会以 **来自 ⬢ 登录：修好不稳定的测试 的消息** 出现在聊天里，智能体随即接手：对照你的要求检查成果，缺了什么就给编程智能体补充指示，然后告诉你结果。编程智能体自己停下时，也会这样说明原因。

聊天里的 **停止** 会连同智能体的工作一起停掉聊天里的编程智能体。退出 Lorca 会停止正在工作的编程智能体；已经做完的，之后还能接着补充指示，从上次停下的地方继续。编程智能体的运行时间，计入启动它的那一轮的[上限](/zh/docs/limits)。
