一个群聊可以有一到六个智能体。它们都能读到整个对话，并且轮流发言，而不是抢着说。

## 开始群聊

在标题栏的 Create 按钮里选择 **新建群聊…**，选最多六个智能体。之后可以在聊天的检查器里添加或移除智能体，在侧边栏或检查器里给聊天重命名。

群里的智能体可以运行在不同的电脑上。Lorca 会把每一轮送到对应的 Runner。

## 群聊是做什么的

给群聊写一段描述，群里的每个智能体每一轮都会读到：这个群是干什么的、哪些事归它管、做到什么程度算完成。在聊天检查器的 **群聊** 部分点描述旁边的 **编辑…** 来设置，手机上在 **群聊信息** 里设置。

## 项目

群聊检查器里 **群聊** 下面的 **项目** 部分（手机上在群聊的详细信息里），存放群里每个智能体都该知道、并始终记着的内容：简介、目标、约束、决定、事实、链接和文件。每个智能体每一轮都会看到它的简短索引，工作需要时再读具体条目，所以长聊天被压缩后它依然在。它只属于这个群聊；每个智能体自己的[记忆](/zh/docs/memory)是分开的。

- **添加：** **+** 菜单可以添加简介、目标、约束、决定、事实、链接或文件。
- **建议：** 智能体可以提议条目，在你 **接受** 之前，它会显示为“某某的建议”。
- **链接：** 智能体依赖某个链接的内容之前会重新查看一次，默认超过一天就会重查。条目会显示上次查看的时间；**立即检查** 会马上查看，打不开的链接会标成橙色。
- **修改：** 点一个条目可以修改或 **移除…** 它。两台设备同时改了同一条时，它会标成橙色：用 **保留这个版本** 选定一个。

群聊还可以有自己的[技能](/zh/docs/skills)，群里每个智能体都能在这里使用；也可以有[任务](/zh/docs/tasks)，每个任务由群里的一个智能体负责。

## 轮次是怎么走的

你发一条消息后，每个智能体依次被点到一次：

1. 你用 `@` 提到的智能体排在最前，其余按群里的顺序。
2. 智能体要么在群里回复，要么**跳过**。跳过是无声的，不会变成一条消息。
3. 只要有人回复，就再来一轮，只点那些听到了新内容的智能体。
4. 一轮里没人说话，或者第四轮结束后，这次交流就结束。

再发一条消息会调整群聊的方向。当前轮到的智能体会先完成这一轮，包括正在运行的命令；然后旧交流让出执行权，从你的新消息开始新一轮交流。**停止响应** 会立即打断。

<Callout title="引导谁来回答">
  @ 某个名字，那个智能体排到最前。`@everyone` 让所有智能体都开口。不提任何人，就由智能体们自己判断谁有话要说。
</Callout>

Runner 离线的智能体会被跳过，群聊继续往下走。

## 负责人

每个群聊都有一个负责人：手上拿着这项工作的智能体。群里每个智能体都知道是谁。负责人一开始是你选的第一个智能体。要更换，在聊天的检查器里点击或右键点按一个智能体，选择 **设为负责人**；在手机上，在聊天详情里轻点一个智能体。在终端里：

```bash
lorca chats set-owner "Launch room" Developer
```

负责人离开群聊后，群里剩下的第一个智能体接任。

## 群聊还是单聊？

- 当几个智能体需要同一份上下文时用**群聊**：站会、评审、涉及多个岗位的计划。
- 单个智能体的工作用**单聊**。需要别人时，它仍然可以[给其他智能体发消息](/zh/docs/chats#智能体之间互相发消息)。

同一个群里的智能体就在群里交流。它们不能给同群的成员私下发消息。
