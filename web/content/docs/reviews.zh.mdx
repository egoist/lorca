智能体有些工作要等你点头才会离开你的电脑：它写的邮件和 Slack 消息，以及[例行任务](/zh/docs/routines)或事件本来要问你的操作。你在任何一台设备上做决定，由智能体的 Runner 去执行。

## 邮件和 Slack 草稿

智能体在聊天里用 Gmail 写邮件、用 Slack 写消息时，不会直接发出去。消息会以草稿卡片的形式出现在聊天里：“幕僚长 起草了一封邮件”（或“一封回复”“一条 Slack 消息”），下面是账号、收件人、抄送、密送和主题，正文和附件。

- **修改**：每个字段都可以直接改，也可以去掉某个附件。
- **发送**：按卡片上的样子发出。之后卡片显示“已发送”，或“未发送”并附上服务给出的原因。
- **舍弃**：丢掉这份草稿。
- **始终发送**：只在 Slack 卡片上有。发出这条消息，并让这个智能体以后直接发送 Slack 消息。

在手机上，轻点卡片会以写信界面打开这条消息。智能体在下一轮会读到草稿最后怎么样了、你改了什么；你的修改也会作为[反馈](/zh/docs/feedback)被它记住。

每个智能体默认都先写草稿。要让某个智能体直接发送，在它的[访问权限](/zh/docs/access)里关掉 **先写草稿**：它的 Slack 消息会在[自动审查](/zh/docs/auto-review)后直接发出，Gmail 则把草稿放进你邮箱的草稿箱。你为智能体保存的[密钥](/zh/docs/secrets)永远不会出现在消息里。

## 等待审核

例行任务或事件运行时没人在场，所以本来要先问你的操作不会执行，而是留下来等你：可能是智能体发起的那条命令或插件调用，原样保留；也可能是一份等你接受的草稿。智能体也可以主动把工作留给你审核。

只要聊天里的智能体有待审核的内容，检查器里智能体列表下方就会出现 **等待审核**，最早的排在前面（手机上在聊天的详细信息里）。点开一项，可以看到智能体想做什么、为什么，以及那条命令、调用参数或草稿，内容都可以改。

- **批准**：在智能体的 Runner 上执行一次输入框里的内容。如果你改过，会先保存修改。
- **拒绝**：丢弃它。**取消** 只是关闭面板，这一项继续等着。

聊天里会为每一项留一行说明，比如“Waiting for your review · $ git push origin main”，结束后会变成完成、失败、已拒绝或未完成，并在下面附上输出。如果它依赖的东西变了，比如某个文件或智能体的设置，它会再次请你审核。执行到一半被打断、没有拿到结果的调用显示为未完成，因为它可能已经生效；Lorca 不会自动重试。

[关注事项](/zh/docs/attention)会汇总所有聊天里等你审核的内容。
