`lorca` 才是真正干活的程序：它持有你的密钥，和中继、AI 服务商通信，并运行智能体。它支持 macOS、Linux 和 Windows。桌面应用内置了它，并替你启动；在没有桌面应用的电脑上，自己运行 CLI，那台电脑就是一个 Runner。

在 macOS 上，应用自带的可执行文件位于 `Lorca.app/Contents/Resources/bin/lorca`。

## 安装

在没有桌面应用的 Apple 芯片 Mac 或 Linux 电脑上：

```bash
curl -fsSL https://lorca.app/install-cli.sh | sh
```

在 Windows 上，打开 PowerShell：

```powershell
irm https://lorca.app/install-cli.ps1 | iex
```

脚本会下载适合这台电脑的最新版本，用该版本的校验和核对下载的文件，把 `lorca` 放进 `~/.local/bin`，并把这个文件夹加入 PATH。之后 `lorca` 会[自己更新](#更新)。

设置 `LORCA_VERSION=1.0.0` 安装指定版本，设置 `LORCA_INSTALL_DIR` 把 `lorca` 放到别的文件夹，设置 `LORCA_NO_MODIFY_PATH=1` 则不改动 PATH：`curl -fsSL https://lorca.app/install-cli.sh | LORCA_VERSION=1.0.0 sh`；在 PowerShell 里，先运行 `$env:LORCA_VERSION = '1.0.0'` 再运行 `irm`。

在 Windows 上，智能体用 Git for Windows 自带的 bash 运行命令，不用 WSL 的 bash，所以也要安装 [Git for Windows](https://git-scm.com/downloads/win)。Lorca 会在 Program Files、只为当前用户安装的位置，或 PATH 上的 `git` 旁边找到它；安装之前，智能体的命令会失败，并提示需要安装。

## 命令

| 命令 | 作用 |
| --- | --- |
| `lorca` | 列出所有命令。 |
| `lorca serve` | 运行服务。 |
| `lorca identity new` | 创建身份并打印备份短语。 |
| `lorca identity restore <phrase>` | 用备份短语恢复身份。 |
| `lorca identity show` | 显示这台设备的身份。 |
| `lorca pair` | 显示配对字符串，并等待另一台设备。 |
| `lorca pair <string>` | 用配对字符串加入一个账户。 |
| `lorca provider set <kind> [api-key]` | 接入 `deepseek`、`anthropic`、`opencode`、`opencode-go`、`chatgpt` 或 `grok`。省略密钥时从标准输入读取；`--base-url` 设置自定义地址。 |
| `lorca provider add <name> <base-url>` | 添加一个自定义服务商：任何兼容 OpenAI 或 Anthropic API 的服务器，或供自动审查使用的决策 API。`--api` 选择 `chat-completions`（默认）、`responses`、`messages`、`system-one` 或 `decisions`；`--model` 指定一个模型，每个模型写一次；`--api-key-stdin` 读取密钥。 |
| `lorca provider remove <kind>` | 在每台设备上断开一个服务商，或删除一个自定义服务商（例如 `custom:openrouter`，以 `provider list` 显示的为准）。 |
| `lorca provider list` | 列出已接入的服务商。 |
| `lorca mcp …` | 管理这台电脑自己的 MCP 服务器；见 [MCP 服务器](#mcp-服务器)。 |
| `lorca chats list` | 列出所有聊天：每个聊天的 ID 和智能体，以及群聊的负责人。 |
| `lorca chats set-owner <group> <bot>` | 把某个智能体设为群聊的[负责人](/zh/docs/group-chats#负责人)。群聊用标题或 ID 指定，智能体用名字或 ID 指定。 |
| `lorca marketplace reload` | 立即向 lorca.app 检查有没有更新的市场。Lorca 启动时、应用连接时，以及你或智能体浏览市场时也会自己检查，最多每小时一次，所以新的插件和智能体无需更新应用就能用上。 |
| `lorca models reload` | 立即向 lorca.app 检查有没有更新的模型目录。Lorca 启动时和应用连接时也会自己检查，最多每小时一次，所以新模型无需更新应用就能用上。 |
| `lorca update` | 立即安装最新版本。正在运行的 `lorca serve` 会在没有智能体工作时重启到新版本。`--check` 只告诉你有没有新版本；`--auto off` 关闭自动更新，`--auto on` 重新打开。 |
| `lorca service install` | 让 `lorca serve` 在后台运行：现在启动，每次登录时启动，停止后会再次启动。`lorca service uninstall` 停止它；`lorca service status` 告诉你它是否在运行、日志在哪里。 |
| `lorca status` | 以 JSON 打印这台设备的状态：设备、智能体、聊天、服务商。 |
| `lorca doctor` | 检查主目录、身份、端口、中继和 `mcp.json`，并指出哪里有问题。 |

## MCP 服务器

`lorca mcp` 编辑 Lorca 文件夹里的 `mcp.json`，也就是这台电脑上所有智能体都能使用的[MCP 服务器](/zh/docs/plugins#你自己的-mcp-服务器)。`lorca serve` 正在运行时，改动会立即生效；没有运行时，下次 `lorca serve` 会读取这个文件。手动编辑文件后，运行 `lorca mcp reload`。

| 命令 | 作用 |
| --- | --- |
| `lorca mcp list` | 列出服务器及各自的状态：它的工具、需要的登录，或者没能启动的原因。`lorca serve` 没有运行时，会先逐个连接。有服务器需要处理时，以状态码 1 退出。 |
| `lorca mcp get <name>` | 连接一个服务器，并显示它的设置和工具。 |
| `lorca mcp add <name> <command> [args…]` | 添加一个由这台电脑运行的服务器。命令后面的所有内容（包括 flag）都是它的参数；在命令前用 `-e KEY=value` 设置变量，每个变量写一次。 |
| `lorca mcp add <name> <url>` | 添加一个使用 streamable HTTP 的远程服务器。`-H "Name: value"` 添加请求头，写在 URL 前后都可以。 |
| `lorca mcp add-json <name> <json>` | 用 JSON 添加服务器，就像 README 或其他应用的配置里写的那样。 |
| `lorca mcp remove <name>` | 移除一个服务器，连同它的登录信息。 |
| `lorca mcp enable <name>`、`disable <name>` | 开启或关闭一个服务器。关闭后，智能体看不到它，它也不会启动。 |
| `lorca mcp sign-in <name>` | 在这台电脑的浏览器里登录一个要求登录的远程服务器。 |
| `lorca mcp sign-out <name>` | 忘掉一个远程服务器的登录。下次使用时它会再次要求登录。 |
| `lorca mcp reload` | 手动编辑 `mcp.json` 之后，让正在运行的 `lorca serve` 重新读取它。 |
| `lorca mcp hide <name> <tool>`、`show <name> <tool>` | 让智能体用不到服务器的某个工具，或重新提供给它们。工具可以写成模式，比如 `delete_*`。 |
| `lorca mcp import [file]` | 从其他应用的配置中添加服务器：Claude Desktop、Claude Code、Cursor、Windsurf、VS Code 或 Gemini CLI，或者你指定的文件。 |

```bash
lorca mcp add notes npx -y @modelcontextprotocol/server-filesystem ~/Notes
lorca mcp add github -e GITHUB_PERSONAL_ACCESS_TOKEN=ghp_… docker run -i --rm -e GITHUB_PERSONAL_ACCESS_TOKEN ghcr.io/github/github-mcp-server
lorca mcp add linear https://mcp.linear.app/mcp
lorca mcp add-json time '{"command": "uvx", "args": ["mcp-server-time"]}'
```

`--description` 告诉智能体服务器的用途，`--timeout` 设置一次调用最多可以多少秒没有回应。`add` 在保存后会连接一次服务器，并告诉你它是否启动成功。

## 无屏幕的 Runner

```bash
export LORCA_RELAY_URL=https://relay.example.com
lorca pair 'lorca://pair?…'   # 来自已有设备上的“配对设备…”或 `lorca pair`
lorca service install
```

这台电脑会出现在你的设备列表里，你可以从桌面应用或手机为它创建智能体。`lorca service install` 让 `lorca serve` 一直运行：在 macOS 上是一个启动代理，在 Linux 上是一个 systemd 用户服务，在 Windows 上是一个登录项。在 Linux 上，它还会请 systemd 在你退出登录后继续运行你的服务；如果这需要管理员权限，它会打印需要运行的 `sudo loginctl enable-linger` 命令。在容器里或其他没有 systemd 的地方，请用你自己的 init 或在 tmux 里运行 `lorca serve`。

## 更新

用脚本安装的 `lorca` 会自己更新。`lorca serve` 启动几分钟后检查最新版本，之后每天检查一次，安装更新的版本，并在没有智能体工作时重启到新版本，不会打断正在进行的对话。它只安装用 Lorca 更新密钥签名的版本，并在替换任何文件之前，用签名的清单核对下载的文件。如果新版本启动后总是很快停止，它会换回之前的版本。

**设置 › 设备** 显示一台电脑运行的版本。有更新的版本时，可以在你的任何一台设备上点 **更新** 来安装，所以你也能从手机更新一台 Runner。装了桌面应用的电脑则随应用一起更新。

在 Windows 上，重启到新版本需要 `lorca service`；没有它时，`lorca serve` 会一直运行旧版本，直到你再次启动它。

## 环境变量

| 变量 | 设置什么 |
| --- | --- |
| `LORCA_HOME` | 密钥、凭据和聊天的存放位置。默认 `~/.lorca`。 |
| `LORCA_PORT` | 应用连接的本地端口。默认 `4862`。 |
| `LORCA_RELAY_URL` | 中继地址。 |
| `LORCA_SHELL` | 智能体运行命令所用的 shell。默认 `/bin/bash`；在 Windows 上是 Git for Windows 的 bash。在 macOS 和 Linux 上，无论用哪个 shell，命令都会得到你的登录 shell 的 `PATH` 和环境变量。 |
| `LORCA_DEEPSEEK_MODEL`、`LORCA_ANTHROPIC_MODEL`、`LORCA_CHATGPT_MODEL`、`LORCA_GROK_MODEL` | 没有指定模型的智能体使用的默认模型。 |
| `LORCA_MODELS_URL` | Lorca 检查更新模型目录的地址。默认 `https://lorca.app/models/v1.json`；设置 `LORCA_MODELS_FETCH=0` 则不再检查。 |
| `LORCA_MARKETPLACE_URL` | Lorca 检查更新市场的地址。默认 `https://lorca.app/marketplace/v1.json`；设置 `LORCA_MARKETPLACE_FETCH=0` 则不再检查。 |

## 文件

一切都在 `~/.lorca/` 下，只有你的用户可读：身份和机器密钥、服务商凭据、设置、聊天、附件、插件、`mcp.json` 里你自己的 MCP 服务器、`catalog.json` 里最近一次获取的模型目录、`marketplace.json` 里最近一次获取的市场、`update.json` 里最近一次的更新检查、`serve-token` 里应用和 `lorca` 连接正在运行的 `lorca serve` 所用的令牌（网页连不上它），以及每个智能体一个的工作区文件夹（里面有它的记忆）。

macOS 应用把服务的日志写到 `~/Library/Logs/Lorca/cli.log`。使用 `lorca service` 时，日志在 macOS 上是 `~/Library/Logs/Lorca/serve.log`，在 Linux 上用 `journalctl --user -u lorca` 查看，在 Windows 上是 `~/.lorca` 里的 `serve.log`。
