自动审查位于智能体和会产生影响的插件操作或 Runner 上的 shell 命令之间，智能体运行的[编程智能体](/zh/docs/coding-agents)的命令也在其中。它逐个操作地决定：直接运行，还是先问你。

它排在智能体的[访问权限](/zh/docs/access)之后：访问权限不允许的操作根本到不了自动审查，这里的任何规则或回答也不会放宽访问权限。在聊天里，邮件和 Slack 消息不经过它，而是作为[草稿](/zh/docs/reviews#邮件和-slack-草稿)等你亲自发送。

## 权限卡片

当一个操作需要你点头时，智能体会在聊天里发一张卡片：

> 幕僚长想要使用 GitHub · create_issue · repo: acme/api

或者：

> 幕僚长想要在 Workbench 上运行命令
>
> `$ cargo publish`

上面有它暂停的原因。点一下命令可以看到完整内容。在选项下方，shell 命令的卡片会写明自动审查为这类命令提议的规则：

> “始终允许”会添加规则“把 ~/dev/lorca 里的 crate 发布到 crates.io”。

三个选项：

- **允许一次**：运行这一次。
- **始终允许**：运行，并添加一条规则，之后类似的操作会自动运行。对 shell 命令，这条规则就是卡片上那条自然语言规则；你可以像修改自己写的规则一样在设置里改它的措辞。对插件操作，规则对应确切工具。没有提议规则的 shell 卡片（例如自动审查关闭，或由决策模型审查时）只有允许一次和拒绝。
- **拒绝**：拒绝。智能体会被告知不要重试。

你可以在任何设备上回答。智能体最多等十分钟。

## 它怎么判断

自动审查 **开启**时，每个操作都会对照你的规则、你最近的一条消息和内置检查来判断：

- **先问：**删除或覆盖、发布到别人看得见的地方、任何涉及钱或访问权限的事、批量或不可逆的改动。
- **直接运行：**你要求的、范围有限且可以撤销的工作。

自动审查 **关闭**时，每个 shell 命令和每个会产生影响的插件操作都会询问。

只读的插件操作从不询问，只读的 shell 命令也一样：Lorca 会解析命令的每个阶段，只读取内容的命令（如 `git status`、`ls` 或 `rg TODO src | wc -l`）会直接运行。会写入、删除、安装、运行代码或读取密钥和令牌的命令会交给审查模型（见下文），由它根据内置检查、你的规则和你最近的请求作出判断。Lorca 自己的文件夹 `~/.lorca` 和 `~/.lorca-dev` 属于智能体：只在其中操作的命令无论做什么都不用审查。`/tmp` 这样的临时目录算作草稿空间，在里面清理不会询问。

## 审查模型

智能体的操作由它所用服务商的审查模型审查。你也可以在 **设置 › 自动审查 › 审查方式** 里，改由另一个已接入的服务商为所有智能体审查。每个服务商的审查模型在 **设置 › 服务商 › 审查模型** 里：默认是一款小型快速模型，例如 ChatGPT 的 GPT-6 Luna 或 Anthropic 的 Claude Haiku 4.5，你可以改选这个服务商的任意模型：更便宜或更强的聊天模型，或者一款**决策模型**。

决策模型用概率回答问题而不写文字，所以又快又便宜，例如 TypeSafe 的 Jev、OpenRouter 上的决策模型，以及 OpenAI 通过 Decisions API 提供的 GPT-6 Luna。它会选择“允许”，或指出操作可能造成的影响；只有模型至少有 70% 的把握认为安全时，Lorca 才会运行这个操作，否则卡片会写出这项影响。决策模型不会写规则，所以它暂停的卡片只有“允许一次”和“拒绝”；规则请自己在设置里写。要用决策模型，可以接入提供 Jev 1.13（以及免费的 Jev 1.13 Free）的 OpenCode Zen，或把决策 API 添加为[自定义服务商](/zh/docs/providers#自定义服务商)。

如果你选的服务商被断开，就会改回由智能体自己的服务商审查。

## Shell 访问

一个被允许的 shell 命令以你的用户身份运行，拥有你通常的文件系统、进程、凭据和网络访问权限。工作目录只是上下文，不是安全边界。正是这种整机访问能力，让技能可以驱动已安装的 CLI、应用、构建、服务和工作区之外的文件。

自动审查和权限卡片就是边界。Lorca 会在启动命令前审查完整命令；拒绝一个暂停的操作后，其中任何阶段都不会运行。

## 规则

打开 **设置 › 自动审查** 可以开关它，并用自然语言写规则：

> 当智能体想要…：在 pull request 下评论 → **先询问**
>
> 当智能体想要…：给我自己仓库里的 issue 打标签 → **自动允许**

“始终允许”添加的规则也在这里。两条规则冲突时，Ask first 优先。规则会同步到你所有的设备，并对每个智能体生效。

## 例行任务和事件

[例行任务](/zh/docs/routines)、[事件](/zh/docs/events)或[频道](/zh/docs/channels)里的消息运行时，没有人看着。自动审查允许的操作（包括你的规则涵盖的）仍会运行。本该询问的操作会留下来等你审核：它出现在[等待审核](/zh/docs/reviews#等待审核)里，你批准后才运行。

事件的内容、频道里别人写的话，都不会被当成你的要求：自动审查会对照你设定的任务来判断每一个操作。
