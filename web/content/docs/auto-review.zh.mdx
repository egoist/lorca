Auto-review 位于智能体和那些会改动东西的插件操作之间。它逐个操作地决定：直接运行，还是先问你。

## 权限卡片

当一个操作需要你点头时，智能体会在聊天里发一张卡片：

> Chef wants to use GitHub · create_issue · repo: acme/api

上面有它暂停的原因，以及三个选项：

- **Allow once**：运行这一次。
- **Always allow**：运行，并添加一条规则，这个工具以后不再询问。
- **Deny**：拒绝。智能体会被告知不要重试。

你可以在任何设备上回答。智能体最多等十分钟。

## 它怎么判断

Auto-review **开启**时，每个操作都会对照你的规则、你最近的一条消息和内置检查来判断：

- **先问：**删除或覆盖、发布到别人看得见的地方、任何涉及钱或访问权限的事、批量或不可逆的改动。
- **直接运行：**你要求的、范围有限且可以撤销的工作。

Auto-review **关闭**时，每个会改动东西的操作都会询问。

只读操作，比如列出 issue 或抓取页面，从不询问。

## 规则

打开 **Settings › Auto-review** 可以开关它，并用自然语言写规则：

> When a bot wants to: comment on a pull request → **Ask first**
>
> When a bot wants to: label issues in my own repos → **Allow automatically**

两条规则冲突时，Ask first 优先。规则会同步到你所有的设备，并对每个智能体生效。

## 例行任务

[例行任务](/zh/docs/routines)运行时没有人看着，所以本该询问的操作会被直接拒绝。为例行任务需要独立完成的事添加一条允许规则。
