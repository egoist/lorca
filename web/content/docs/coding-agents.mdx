A bot can hand a coding job to a coding agent on its Runner: **Claude Code**, **Codex**, **OpenCode**, **pi**, or Vercel's **fx**. The agent works on its own in a branch of its own; the bot tells you it started it, checks its work when the agent is done, and tells you how it went, with the pull request when there is one.

## Start one

Ask the bot:

> Fix the flaky login test in ~/dev/app and open a pull request.

The bot gives the job a short title and a brief, starts the agent, and the chat shows **Messaged ⬢ Login: fix the flaky test** with the agent's logo. Starting one needs **Shell commands** in the bot's [Access](/docs/access).

The agent works in the folder the bot gives it, as it would if you started it there in a terminal: it decides how, a branch or a worktree of its own included. If you want the work on a new branch or kept out of your checkout, say so, and the bot tells the agent.

## Which agent

Each computer that runs bots keeps its own list of the five, in your order of preference, each with a switch. Find it under **Settings → Coding Agents** with that computer picked at the top (on the phone, under the computer in **Settings**). The list shows whether each agent is installed there and its version, and you drag an agent to change the order. A bot uses the first one that is on and installed on its computer, unless you ask for another ("have Codex do it"). Install the agent and sign in to it on that computer, as you would in a terminal.

## What it may do

Every command the agent runs goes through the bot's Access and [Auto-review](/docs/auto-review), as the bot's own commands do. Commands that only read, and work inside its folder, run at once; a push or a deploy is weighed against what you asked for. When Auto-review asks you, the card under the agent's marker reads "Claude Code wants to run a command" with the command, **Allow once**, **Always allow**, and **Deny**, on any of your devices.

A bot can give an agent [secrets](/docs/secrets) it saved for commands, such as `NPM_TOKEN` to publish a package. The agent has them in its environment; its transcript and messages show their names, never their values.

## Follow its work

Click the agent's marker in the chat, or its row under **Coding** in the chat's details, to open its page: what the bot asked, what it thought and said, the files it explored, the commands it ran, the edits it made with lines added and removed, and its plan, as they happen. The page shows its branch and pull request, and **Stop** while it works. It is read-only: to change course, tell the bot, which sends the agent a follow-up.

The **Coding** list shows each agent's title and how it stands: **Working**, **Needs attention** (it waits for your answer), **Ready for review** (done, with a pull request), **Finished**, **Run failed**, or **Stopped**.

## When it is done

When the agent finishes, what it said lands in the chat as **Message from ⬢ Login: fix the flaky test**, and the bot picks it up: it checks the work against what you asked, sends the agent a follow-up if something is missing, and tells you how it went. An agent that stops on its own says why the same way.

**Stop** in the chat stops the chat's coding agents along with the bot's work. Quitting Lorca stops the agents at work; one that was done can take a follow-up later and picks up where it left off. The agent's run time counts toward the [limits](/docs/limits) of the turn that started it.
