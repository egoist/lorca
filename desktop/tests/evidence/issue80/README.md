# Native Go/MyGo output evidence

These frames are generated by production native Go/MyGo views in `ui.NewTester` on a macOS host, using the existing synthetic demo and a fixture CLI transport. They are not photographs of a running Windows or Linux installation. The screenshots show actual keyed native views, sheets and controls; no webview or HTML replica is used. Demo credentials and messages are synthetic.

- `desktop-before.png`: main-window fixture at merge baseline `99daa10`, before the desktop Outputs entry exists.
- `desktop-after.png`: the same main-window demo with the Outputs entry in the header.
- `outputs-header.png`: the Outputs button over the output-version fixture chat.
- `outputs-versions-{light,dark}.png`: immutable v1/v2 report metadata, producing bot/task provenance and synthetic test results.
- `outputs-unavailable-{light,dark}.png`: a fixture CLI returns an unavailable-file error; the sheet displays its reason and Retry.
- `outputs-file-ready-{light,dark}.png`: Retry succeeds through `files.path` with `named: true`; Preview, Open and Save As appear for the retrieved local file.
- `outputs-text-preview-{light,dark}.png`: the native bounded text preview, returning to the Outputs sheet on Escape.
- `outputs-image-preview-{light,dark}.png`: native preview of a generated sample PNG.

Regenerate the current native frames:

```sh
cd desktop
LORCA_RENDER=tests/evidence/issue80 go test . -run 'TestOutputs|TestOutputImagePreview|TestCopyOutput' -count=1
```

The before image remains a historical capture. The tester clicks real native controls. Save tests copy actual temporary bytes to an approved fixture destination; native save-dialog and system-open functions are substituted so the tests start no outside app and modify no user files. All fixtures use temporary folders and the post queue for asynchronous replies. Assets under this directory are not included in app resources or production bundles.

Windows x64 and Linux x64/arm64 builds are checked separately. Live Windows/Linux operation, native OS dialogs/system handlers, paired-device end-to-end retrieval, external document reachability and consolidated #72/#85 execution remain unexercised. The original #80 Rust tests establish encrypted file retrieval on a distinct paired Device; these UI fixtures do not establish those combined/live workflows.
